## 1. 벤치마킹 대상 선정

우리 프로젝트의 성격이 특이하다. **여행 계획은 이미 끝났고, 남은 것은 현장 실행**이다. 43일 일정과 원고가 확정돼 있다. 따라서 "일정을 짜 주는" 제품은 참고 가치가 낮고, "확정된 일정을 현장에서 쓰게 하는" 제품이 핵심이다.

| 군 | 대상 | 우리가 볼 것 |
|---|---|---|
| A. 종이 가이드북 | Michelin Green Guide, Lonely Planet, Rick Steves | 등급 체계·정보 위계 |
| B. 여행 플래너 앱 | Wanderlog, TripIt, 트리플 | 현장 화면 구성·오프라인 정책 |
| C. 오프라인 지도 | Organic Maps | 무연결 환경 해법 |
| D. 맞춤여행사 | Audley Travel | 확정 일정 문서의 전달 형식 |

## 2. A군 — 종이 가이드북

### 2.1 Michelin Green Guide

3단계 별점을 쓰는데, **등급 언어가 "얼마나 좋은가"가 아니라 "얼마를 지불할 가치가 있는가"로 되어 있다.**

| 별 | 문구 |
|---|---|
| ★ | 방문할 가치 (worth a visit) |
| ★★ | **우회할** 가치 (worth a detour) |
| ★★★ | **특별한 여정을 떠날** 가치 (worth a special journey) |

레스토랑 적자 기준도 동일한 구조다 — 한 별은 들를 가치, 두 별은 우회할 가치, 세 별은 특별한 여정의 가치. <cite index="36-4,40-1">한 별은 들를 만한 고품질, 두 별은 우회할 만한 훌륭한 요리, 세 별은 특별한 여정을 감수할 만한 예외적 요리를 뜻한다.</cite>

**시사점:** 등급이 곧 **행동 지시**다. 여행자는 "이게 좋은가"가 아니라 "여기에 시간을 얼마나 쓸까"를 판단한다. 우회할 가치라는 말에는 이미 이동 비용이 들어 있다.

우리 사이트의 5단계(필수/우선추천/선택/대체/제외)는 논리적으로 정확하지만 **비용 언어가 없다.** "우선추천"은 얼마짜리인지 알려주지 않는다.

### 2.2 Lonely Planet / Rick Steves 계열

*(공식 문서 미검증. 일반 지식 기반 — 참고용)*

두 계열의 공통 장치는 **"시간이 부족하면 이것만"** 블록이다. 3일/1주/2주 코스를 미리 잘라 준다. 여행자가 현장에서 삭제 판단을 하지 않아도 되게 만든다.

우리 사이트는 이미 챕터마다 `우선 삭제`·`대체안`·`지연 시 대체`를 갖고 있다. **이 부분은 상용 가이드북 수준을 이미 넘는다.**

## 3. B군 — 여행 플래너 앱

### 3.1 Wanderlog

<cite index="15-1">공개 기능 페이지는 일정 계획, 지도 보기, 협업, 예약, 숙소, 항공 상태, AI 지원, 짐 체크리스트, 여행 가이드, 예산, 경로 최적화, 오프라인 접근을 내세운다.</cite> <cite index="18-1">단일 목적지에 최적화된 다른 플래너와 달리 복잡한 다도시 일정과 로드트립에 강하고, 지도 인터페이스가 목적지 간 공간 관계를 파악하는 데 유용하다.</cite>

**우리가 배울 것:** 일정 항목과 지도를 **같은 화면**에서 본다. 목록만 보면 "이 세 곳이 서로 가까운가"를 알 수 없다.

**반면교사:** <cite index="16-1">기본 UI 기능인 다크모드까지 유료로 막아 상당한 반발을 샀다.</cite> <cite index="12-1">오프라인 접근은 무료판에서 제한되고 프리미엄에서만 완전히 제공된다.</cite>

→ **오프라인과 다크모드·글자 크기는 접근성 기능이지 부가 기능이 아니다.** 우리는 유료화가 없으니 해당 없지만, "부가 기능" 취급해 후순위로 미루는 실수는 똑같이 가능하다.

### 3.2 TripIt

<cite index="15-1">항공·호텔·렌터카·예약 확인 메일이 이미 있다면 TripIt이 그 확인서를 정리하도록 만들어졌다.</cite>

예약 확인 메일을 자동으로 일정으로 조직한다. **우리 트래커 6종이 이 역할을 이미 한다.** 다만 결정적 차이가 있다 — TripIt은 확정된 예약만 다루는데, 우리는 **미확정 상태를 안고 출발**한다.

### 3.3 트리플 (한국)

<cite index="20-1">일정 생성부터 정보 제공·상품 추천까지 AI가 처리하고, 갈 곳을 고르면 동선과 일정이 만들어지며, 여행 가계부와 235개 도시 가이드, 날씨·환율·번역·시차·길찾기를 한데 모았다.</cite> <cite index="21-1">나만의 장소를 추가하고 메모하며 날마다 필요한 체크리스트를 만들 수 있다.</cite>

**시사점:** 한국 여행자가 이미 학습한 인터랙션 패턴이 있다. 날짜 탭 → 그날 타임라인 → 지도 토글 → 체크리스트. 우리 사이트가 이 관습에서 크게 벗어나면 학습 비용이 생긴다.

**단** 트리플의 본질은 예약 커머스다. AI 일정 생성·상품 추천·라운지는 우리에게 불필요하다.

## 4. C군 — 오프라인 지도

### 4.1 Organic Maps — 이번 벤치마킹 최대 수확

<cite index="47-1">OpenStreetMap 데이터를 쓰는 무료 오프라인 지도 앱으로, 도보·자전거·자동차 턴바이턴 음성 안내, 오프라인 검색, 다크 모드를 제공하며 KML·KMZ·GPX·GeoJSON 형식의 북마크·트랙 가져오기와 내보내기를 지원한다.</cite> <cite index="49-1">국가·지역 데이터가 용량을 많이 차지하지 않고 광고·추적이 없다.</cite>

**결정적 사실:** 우리 사이트에는 이미 **도시별 KML 8개와 GeoJSON 8개**가 있다.

즉 우리가 오프라인 지도 타일을 직접 구현할 필요가 전혀 없다. 여행 전에 KML을 Organic Maps에 임포트하면:

| 얻는 것 | 우리가 만들 경우 |
|---|---|
| 프랑스·스페인 전역 오프라인 지도 | 불가능 (용량) |
| 65개 핀 그대로 표시 | 이미 있음 |
| 도보·운전 턴바이턴 음성 안내 | 불가능 |
| 오프라인 검색 | 별도 구현 |
| 개발 공수 | **0일** |

우리 사이트는 안내 페이지 1장만 만들면 된다. 이건 지금까지 나온 개선안 중 **투입 대비 효과가 압도적으로 크다.**

## 5. D군 — 맞춤여행사 Audley Travel

<cite index="34-1">기획 과정은 복잡한 여정의 경우 2–6주가 걸리며, 각 숙소·이동·경험을 가격까지 담은 상세 문서를 받는다.</cite> <cite index="34-1">해당 지역에 거주했거나 광범위하게 다녀 본 국가 전문가가 어떤 속도가 맞는지, 이른 출발이 괜찮은지, 완벽한 하루란 어떤 모습인지 등을 묻고 그 답을 일정에 반영한다.</cite>

<cite index="27-1">브로슈어조차 가이드북식 서술에서 벗어나 "이 목적지를 우리와 함께 가면 어떤 모습인가"를 보여주는 데 집중한다.</cite>

**냉정한 평가:** 우리 사이트의 원고는 **이미 Audley가 파는 문서 수준이거나 그 이상**이다. 챕터마다 피로도, 권장 출발 시각, 최고 리스크, 삭제 순서, 우천 대체안, 심지어 Girona Day 4의 렌터카 반납 2안 병기까지 있다. 유료 맞춤여행사도 여기까지 쓰지 않는다.

**부족한 것은 문서의 품질이 아니라 현장 전환 레이어다.** Audley의 문서는 여행 전에 읽는 것이고, 우리는 걸으면서 읽어야 한다.

## 7. 도출된 개선점

### 7.1 채택 — 즉시

| # | 개선 | 근거 | 공수 |
|---|---|---|---:|
| 1 | **KML 임포트 안내 페이지** — Organic Maps에 8개 도시 KML을 넣는 방법 | 오프라인 내비게이션을 개발 없이 확보 | 0.3일 |
| 2 | **데일리 화면 텍스트화** — PNG 대신 감사표 11필드 렌더, PNG는 하단 보조 | 하루 8–15회 열리는 화면이 이미지 1장 | 1.5일 |
| 3 | **등급에 행동 비용 언어 병기** — Michelin 방식 | "우선추천"이 얼마짜린지 안 알려줌 | 0.3일 |
| 4 | **확정/미확정 이원 표기** | 전 벤치마크에 없는 우리만의 필요 | 0.5일 |
| 5 | **다크모드·글자 크기를 1급 기능으로** | Wanderlog 반면교사 | CSS 완료 |

#### 1번 상세 — 가장 값싼 승리

```
도구 → 오프라인 지도 준비

1. Organic Maps 설치 (무료·광고 없음)
2. 프랑스·스페인 지도 다운로드 (Wi-Fi에서)
3. 아래 KML 8개를 순서대로 열기 → "Organic Maps로 열기"
   Barcelona.kml  Girona.kml  Nice.kml  Aix.kml
   Luberon.kml  Avignon.kml  Lyon.kml  Paris.kml
4. 앱 안에 65개 핀이 북마크로 들어감
```

이 페이지 하나로 우리가 못 만드는 것(오프라인 턴바이턴 안내, 프랑스 전역 지도, 오프라인 검색)을 전부 얻는다. **KML은 이미 저장소에 있다.**

#### 3번 상세 — 등급 언어

| 현재 | 병기할 문구 |
|---|---|
| 필수 | 이것 때문에 이 도시에 왔다 |
| 우선추천 | 반나절을 낼 가치 |
| 선택 | 시간이 남으면 |
| 대체 | 비 오거나 예약 실패 시 |
| 제외 | 이번 일정에선 비용이 값어치를 넘음 |

등급 기호는 그대로 두고 툴팁·범례에 한 줄씩 붙인다.

## 8. 결론

### 8.1 벤치마킹의 결론은 "재편 불필요"

4개 군 어디와 비교해도 **콘텐츠 우위가 명확하다.** 구조를 바꿔서 얻을 게 없다. 벤치마킹이 알려 준 것은 새로운 구조가 아니라 **세 가지 구체적 구멍**이다.

1. 가장 자주 여는 화면이 이미지 한 장이다
2. 오프라인 지도가 없는데, 이미 가진 KML로 해결된다
3. 등급이 행동 비용을 말하지 않는다
