## 2. 메뉴 구조

```

[2] 드로어 (☰)     검색창
                   🏠 홈 — 여정 타임라인

                   ── 지역 가이드 (8, 체류기간 병기)

### 2.2 챕터 내부 구조 — 11대 카테고리

**8개 지역 챕터 전부 동일한 H1 골격을 갖는다.** 이건 잘 된 부분이다.

```
Chapter NN. 지역명
├ 지역소개    Editor's Verdict · 다섯 개의 층 · 핵심 이해
├ 일정        Quick Reference · 전체 일정표 · 동선 도식 · Day 1~N
├ 여행정보    추천 등급 · 체류기간 이벤트 · 핵심 장소 · 꼭 체험할 것
├ 먹거리      시장 · 식당 역할표 · 카페 · 식당 큐레이션
├ 교통        주차 · 운전 · 안전
├ 숙박        생활권 · 숙소 형태 · 후보 · 평가표
├ 예약        예약 카드 · 확정사항과 미결정
├ 경비        참고처
├ 여행팁      운동·휴식 · 우천 대체 · 출발 전 확인 · 현장 선택 규칙

여행자가 현장에서 찾는 축("어디서 자지", "뭐 먹지", "주차 어디")과 정확히 맞는다.

### 2.4 스크립트 동작

`nav.js` (4.7 KB) — 점진적 향상 방식으로 잘 짜여 있다.

| 기능 | 구현 |
|---|---|
| 오늘 버튼 | **`Europe/Paris` 시간대 기준** 날짜 → `GUIDE.today` 맵으로 해당 daily 페이지 이동 |

## 3. 발견된 결함

### 3.1 VISUAL 토큰 68개가 화면에 그대로 노출 — 심각

`{{VISUAL:VIS-MAP-048|type=map|status=linked|strategy=execution-map}}` 형식 문자열이 **제목(H3)으로 렌더되고 있다.**

| 페이지 | 노출 수 |
|---|---:|
| 10 Lyon | **24** |
| 11 Paris | **20** |
| 06 Nice | **15** |
| 05 Girona | 3 |
| 01 사용법 | 3 |
| 04 Barcelona | 2 |
| 09 Avignon | 1 |
| **합계** | **68** |

zip 원본 챕터에 65개가 있었고, 변환 시 제거되지 않은 채 그대로 통과했다. Lyon 챕터를 읽는 사람은 중괄호 문자열 24개를 보게 된다.

**조치:** 페이지 생성 스크립트에서 정규식으로 제거하거나 실제 자산으로 치환.

```js
/\{\{VISUAL:([A-Z0-9-]+)\|([^}]*)\}\}\s*/g
```

`type=map`인 19개는 제거 후 해당 위치에 실행지도 링크를 넣으면 원저자 의도에 맞는다.

### 3.2 Day 헤딩 레벨이 두 챕터만 다름

| 챕터 | Day 헤딩 레벨 |
|---|---|
| 04 Barcelona | **H3** |
| 07 Aix | **H3** |
| 05·06·08·09·10·11 | H2 |

목차(`details.toc`)와 챕터 서브내비의 Day 칩이 H2 기준으로 만들어진다면, **Barcelona와 Aix에서만 Day 링크가 빠진다.** 하필 여행 첫 구간이다.

### 3.3 섹션 번호가 순서와 어긋남

Girona 챕터의 H2 번호 등장 순서:

```
10 → 1 → 2 → 3 → 4 → 6 → 7 → 8 → 9 → 11 → 14 → 13 → 15 → 5 → 17 → 20 → 12 → 16 → 18 → 19
```

원본 마크다운의 섹션 번호를 유지한 채 11대 카테고리로 재배치해서 생긴 현상이다. 재배치 자체는 옳지만 **번호가 남아 노이즈가 됐다.** "5. 숙소 전략"이 문서 후반 `숙박` 아래에, "10. 지로나를 이해하는 핵심"이 문서 앞 `지역소개` 아래에 있다.

**조치:** 번호를 제거하거나 카테고리 기준으로 재부여.

### 3.4 장소 사진이 오프라인에서 전부 사라짐

`nav.js`가 Wikipedia REST API를 실시간 `fetch`한다. 카드 자체는 유지되지만 **사진은 오프라인에서 0장**이다.

오프라인 우선 원칙과 상충한다. 다만 zip에 이미 CC 라이선스 대표사진 8장이 있으므로, 최소한 지역 대표사진은 로컬 자산으로 바꿀 수 있다.

### 3.5 하단탭 구성

| 탭 | 문제 |
|---|---|
| 홈 | 8구간 타임라인. **일정 탭과 성격 중복** |
| 지역 | **없음.** 8개 챕터가 드로어 2뎁스에만 존재 |

지역 챕터는 하루 1–3회 열리는 콘텐츠의 본체다. 이걸 드로어 뒤에 두고 홈을 탭에 두는 건 우선순위가 뒤집힌 것이다.

### 3.6 실행지도 인덱스 아이콘

8개 카드가 전부 동일한 🗺️ 이모지다. 아이콘이 정보를 전혀 담지 않는다. 지역 액센트 색 리본이나 도시 첫 글자가 낫다.
