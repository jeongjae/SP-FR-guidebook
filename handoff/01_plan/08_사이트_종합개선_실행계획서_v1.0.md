## 0. 먼저 읽을 것 — 절대 규칙

### 0.1 `site/`를 직접 수정하지 마라

이 저장소는 **생성 파이프라인**을 갖고 있다.

```
main 브랜치
├─ source/                    원본 (MD 11챕터, 지도, xlsx)
├─ build/build.py             빌드 스크립트 (1,175행)
├─ build/assets/              style.css, nav.js 등 원본
├─ site/                      ← 빌드 산출물. 직접 편집 금지
└─ .github/workflows/pages.yml  main 푸시 → 자동 빌드 → gh-pages 배포
```

`site/*.html`을 고치면 다음 빌드에서 **전부 덮어써진다.** 모든 변경은 `source/` 또는 `build/`에서 한다.

| 바꾸고 싶은 것 | 건드릴 곳 |
|---|---|
| 본문 내용 | `source/**/*.md` |
| 페이지 구조·템플릿·내비 | `build/build.py` |
| CSS·JS | `build/assets/` |
| 새 페이지 종류 | `build/build.py`에 생성 함수 추가 |

### 0.2 빌드·확인 절차

```bash
pip install markdown openpyxl     # 최초 1회
python3 build/build.py            # site/ 전체 재생성 + 내부 링크 무결성 검사
./serve.sh                        # http://localhost:8000
```

**모든 작업은 로컬 빌드가 통과한 뒤에만 커밋한다.**

### 0.3 회귀 방지

작업 시작 전 현재 `site/`를 스냅샷해 두고, 각 작업 후 diff를 확인한다.

```bash
cp -r site /tmp/site_before
python3 build/build.py
diff -rq /tmp/site_before site | head -50
```

의도한 파일만 바뀌어야 한다.

### T1. VISUAL 토큰 제거 {#t1}

**목적** 본문에 노출된 68개 토큰 제거
**대상** `build/build.py`
**심각도** 높음 · **공수** 0.2일

**내용**

`md_convert()` 이전 단계에 토큰 처리를 추가한다. **원본 MD는 수정하지 않는다** — 다음 원본 갱신 때 다시 들어올 수 있으므로 빌드 단계에서 막는 것이 옳다.

```python
VISUAL_TOKEN_RE = re.compile(r'\{\{VISUAL:([A-Z0-9-]+)\|([^}]*)\}\}\s*')

def strip_visual_tokens(md_text, chapter_slug):
    """인라인 VISUAL 토큰 처리. type에 따라 제거 또는 치환."""
    def repl(m):
        key, attrs = m.group(1), m.group(2)
        t = re.search(r'type=([a-z]+)', attrs)
        t = t.group(1) if t else ''
        if t == 'map':
            return ''      # T10에서 지도 링크로 치환 검토
        return ''          # photo·diagram은 제거
    return VISUAL_TOKEN_RE.sub(repl, md_text)
```

토큰이 **헤딩 줄 전체를 차지하는 경우**(현재 다수)에는 빈 헤딩이 남는다. 제거 후 `^#{1,4}\s*$` 빈 헤딩도 함께 지운다.

**빌드 실패 조건 추가** — 산출물에 토큰이 남으면 빌드를 중단시킨다.

```python
leftover = sum(len(re.findall(r'\{\{VISUAL:', p.read_text(encoding='utf-8')))
               for p in (SITE / "chapters").glob("*.html"))
if leftover:
    raise SystemExit(f"VISUAL 토큰 {leftover}개 잔존 — 빌드 중단")
```

**완료 기준**
```bash
grep -ro "{{VISUAL:" site/ | wc -l    # 0
grep -rEo "<h[1-4][^>]*>\s*</h[1-4]>" site/chapters/ | wc -l   # 0
```

### T5. 미확정·등급·피로도 표기 체계

**목적** 미확정값을 확정처럼 표시하는 것이 이 앱 최대 위험
**대상** `build/build.py` + `build/assets/style.css`
**심각도** 높음 · **공수** 0.5일

**내용**

원본 곳곳에 "실제 예약값은 Phase 8에서 잠근다"가 반복되고, GeoJSON 핀에 `status: "후보 — 실제 예약 후 교체"`가 있다. **숙소 후보 주소를 확정으로 믿고 이동하는 사고가 가능하다.**

MD에서 쓸 인라인 문법을 도입한다.

```
{{badge:pending|재확인}}      → <span class="badge badge-pending">재확인</span>
{{badge:p0|P0 연결}}          → 위험 배지
{{grade:essential|필수}}      → ■ 필수 (모양으로 구분)
```

CSS는 T3의 v2.0에 이미 포함돼 있다 (`.badge-*`, `.grade-*`, `.pending`, `.fatigue`).

적용 대상:
1. `요금·예약` 필드 전체 → `재확인` 배지 (원본이 명시적으로 변동정보로 규정)
2. 지도 핀 중 `status`에 "후보·미정·교체"가 든 것 → `.pending` 점선 테두리
3. P0 연결일 Day 4·7·12·24·28·43 → 위험 배지
4. 추천등급 5종 → 모양 구분 (■ ● ○ ◇ ▨)

**색만으로 정보를 전달하지 마라.** 전부 형태 또는 텍스트를 병기한다.

**⚠ 플래그 3종을 분리하라** — 이전 설계 문서가 이것을 "전환일 7일"로 뭉쳐 **Day 43(귀국 항공)에 경고가 안 뜨는 오류**가 있었다.

```python
P0_CONNECTION  = [4, 7, 12, 24, 28, 43]        # 교통 연결 위험
MAP_TRANSITION = [4, 7, 12, 16, 20, 24, 28]    # 지도 2장 필요
DUAL_CHAPTER   = [12, 16, 20, 24, 28]          # 양쪽 원고 존재
```

**완료 기준**
```bash
# Day 43에 P0 배지 존재
grep -c "badge-p0" site/daily/day-43.html      # ≥1
# Day 16·20에 P0 배지 없음
grep -c "badge-p0" site/daily/day-16.html      # 0
```

**선행** T3

### T11. 챕터 페이지 분할 — Girona 파일럿

**목적** 큰 MD 1개 → HTML 1장 + 앵커 구조는 사진·링크·설명을 붙일 자리가 없다
**대상** `build/build.py` 신규 생성 경로
**심각도** 중간 · **공수** 1.5일 (파일럿) + 챕터당 0.3일

**내용**

**작동하는 프로토타입이 제공된다** (`girona-prototype/`). 마크다운 5개 → HTML 20페이지를 생성한다.

```
content/05/            →   chapters/05/
  meta.json                  index.html          허브
  intro.md                   day-1 ~ day-4       일자 4
  days.md          빌드      place-*.html        방문지 11
  places.md    ──────→       food / transport
  topics.md                  cost / alternatives  주제 4
```

**핵심 설계 — authoring 파일 수 ≠ output 페이지 수.** `places.md` 하나를 편집하면 방문지 페이지 11장이 나온다. 파일 관리 부담 없이 각 방문지가 독립 URL을 갖는다.

프로토타입이 제공하는 것:
- `=== slug | 제목 | 부제` 페이지 분할 마커
- 의존성 0 마크다운 변환기 (헤딩·표·목록·인용·링크·이미지)
- 사진 문법 `![alt](경로 "캡션")` → `<figure>`
- 배지 문법 `{{badge:...}}`, `{{grade:...}}`
- **VISUAL 토큰 자동 제거 안전장치**
- 빵부스러기, 이전/다음, 관람 요령 전용 인용 블록

**통합 방식은 판단에 맡긴다.** 프로토타입 로직을 `build.py`에 흡수하거나, 별도 모듈로 두고 `build.py`에서 호출한다. **기존 단일 페이지 챕터와 분할 챕터가 공존할 수 있어야 한다** (한 번에 8개를 다 바꾸지 않는다).

기존 `chapters/05.html`은 새 `chapters/05/index.html`로 리다이렉트하거나 유지한다. 드로어·검색 인덱스의 링크가 깨지지 않아야 한다.

**완료 기준**
- Girona 20페이지 생성, 내부 링크 무결성 검사 통과
- 나머지 7챕터는 기존 방식 그대로 동작
- 검색 인덱스에 신규 페이지 반영

**선행** T1, T3
