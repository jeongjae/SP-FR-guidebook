## 1. ★ 파서가 이번엔 반대로 과소 검출한다 — false negative 48건

`closed` 값 170건을 새 파서에 직접 통과시켜 본 결과다.

| 분류 | 건수 | 판정 |
|---|---:|---|
| ① 값이 **빈 문자열** | **30** | closed 보유로 집계되지만 실제 값 없음 |
| ② 정기휴무 없음 (연중무휴·매일 개방 등) | 58 | 정상 — 빈 집합이 맞다 |
| ③ **요일이 있는데 파싱 실패** | **48** | ★ **false negative** |
| ④ 파싱 성공 | 30 | |

**③의 실제 내용 — 전부 순수 요일값이다.**

```

```

**원인:** 파서가 "요일 뒤에 휴관 표현이 직접 붙은 것만" 채택한다. 그런데 **필드 이름이 이미 `closed`다.** 값에 '휴관'이라는 단어를 한 번 더 요구하는 것은 중복이고, 실제 데이터의 다수는 `토·일`처럼 요일만 적혀 있다.

**그래서 G1이 698건을 검사했다고 하지만, 실효 검사는 30건이다.** S2로 이월된 요일 미확인 27건이 검출 3건으로 줄어든 것이 이것으로 설명된다.

### T3-0 (최우선) — 파서 양방향 수정

```
① closed 값이 순수 요일 나열이면 그대로 휴무 요일로 채택
   패턴: ^[월화수목금토일](요일)?([·,/ ]*[월화수목금토일](요일)?)*  (+ 괄호 부기 허용)
   예: "토·일" / "월요일" / "화요일 (+5/1)" / "수·목"
② '연중무휴 · 매일 개방 · 상시 개방 · 정기 휴무 없음' → 빈 집합 (현행 유지)
③ hours 값의 영업 요일 범위(화–일, 수–월)의 여집합도 보조 근거로 채택
   — 단 closed 가 명시돼 있으면 closed 가 우선
④ ★ 위 어느 규칙으로도 판정 불가하면 조용히 빈 집합을 만들지 말고
   UNPARSEABLE 로 별도 집계해 건수를 보고한다
⑤ 값이 빈 문자열인 closed 레코드 30건은 **레코드를 지우거나** S3 조사 큐로 보낸다.
   빈 값을 'closed 보유'로 세지 마라
```

**④가 G1d 커버리지 원칙의 세 번째 적용이다.** G1(토큰 0) → G2(스코프 18줄) → 지금 파서(실효 30건). 세 번 다 같은 모양이다 — **비어 있음이 통과로 읽혔다.** 이번엔 집계를 강제해서 막는다.

수정 후 **요일 충돌이 새로 다수 드러날 것이다. 그게 정상이고 이 단계의 목적이다.** 고치지 말고 목록으로 보고하라.

**이것이 왜 심각한가.** 이 인프라 전체가 "같은 사실이 여러 곳에 하드코딩돼 값이 갈라지는 것"을 막으려고 만들어졌다. 그런데 **단일 소스 자체가 한 장소에 두 ID를 갖고 있다.** `versailles`는 값이 있고 `versailles-2`는 비어 있으면, 원고가 어느 토큰을 참조하느냐에 따라 다른 것이 렌더된다 — **막으려던 사고를 인프라가 재현한다.**

부수 증거: `grade`가 essential+priority **120곳**으로 나온다. 진단 기준은 101곳이다. 초과분 19가 중복쌍 18과 거의 일치한다.

### T3-1 — 병합 (토큰 이관보다 먼저)

- 18쌍을 검토해 **동일 장소면 병합, 별개면 ID를 구분되게 개명**한다
  - 병합: `arles`/`arles-2`, `versailles`/`versailles-2`, `croix-rousse`/`croix-rousse-2` 등 숫자 접미형
