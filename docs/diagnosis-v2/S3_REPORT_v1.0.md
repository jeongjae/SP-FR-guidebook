
### 원인 — `apply_grades.py` 의 두 가지 버그

2. **등급을 올리기만 하고 내리지 못했다.** 매트릭스가 `excluded` 라고 말하는

둘 다 고쳤고, 스크립트를 **멱등·병합 인지형**으로 만들었다 (정본 ID 표를 참조해 폐기된 ID 를

자모로 쪼개고 뒤 필터가 통째로 날려 **모든 한글 이름이 빈 문자열이 되어 서로 같은 장소로
매칭된다.**

### 101 이 아니라 105 인 이유

| `monaco` · `collioure` | 하위 항목(Le Rocher · Château Royal 등)을 담는 도시 |

## 7. T3-4 — G2 스코프 정상화 (18줄 → 318줄 · FAIL 0)

**스코프를 좁힌 범인은 `OPS_HINT` 였다.** 운영정보 여부를 말(휴관·요금·영업…)로 알아내려 한
것인데, `MONEY`/`TIME`/`WEEKDAY` 가 이미 사실값만 고른다. 이 조건을 없앴다.

- 시간표 행을 코드에 숨기지 않고 `allow_hardcode.txt` 에 **정규식으로 명시**했다
  (허용목록이 `re:` 를 받도록 했다). 숨겨 두면 스코프가 왜 좁은지 아무도 모른다
- **표 행의 주어는 첫 칸이다.** 다른 칸에 이름이 스쳤다고 그 장소의 운영정보로 세지 않는다 —
  `| El Castell de Sitges | La Zorra 예약 실패 | €19.50 |` 의 요금은 La Zorra 것이 아니다
- `if not s or …: pass` 가 **아무것도 건너뛰지 않고 있었다.** 빈 줄만 빼도록 고쳤다
  (`SKIP_LINE` 을 그대로 쓰면 표 행까지 빠져 스코프가 다시 무너진다)
- 남은 하드코딩 28건 처리 — 일정·예산은 허용목록으로, 시설 사실은 place-facts 로 옮기고
  토큰으로 바꿨다. **값은 그대로 두고 집만 옮겼다**

### ★ 커버리지 원칙 3차 적용

검사 대상이 전체의 **1% 미만이면 PASS 가 아니라 WARN**. 이 프로젝트는 같은 실패를 세 번 했다 —
G1 토큰 0 · G2 스코프 18줄 · closed 파서 실효 30건. 셋 다 "거의 아무것도 안 봤는데 통과"였다.

## 9. 정보항목 충족률 — 대리지표
