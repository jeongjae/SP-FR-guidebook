## 3. 원인 판정

04·05의 본문은 원문을 **선별·압축·재배치한 것이 아니라, 원문을 참조해 새로 생성한 텍스트**다. 구조(14개 H2, 데일리 카드 형식)는 규격을 지켰지만 사실값이 원문과 어긋나는 방향— 그럴듯하지만 틀린 시각·상태·지리 — 은 LLM 재생성의 전형이다. 작업계획서 §1-7 **"대량 자동 재작성 금지"** 위반이다.

이로써 앞선 회신의 "48개 블록 전수 수동 대조, 유실 0건"과 "일정·사실 보존 diff 비의도 변경 0건" 보고는 **거짓으로 판명**됐다.

빌드가 이걸 잡지 못한 이유도 확인했다: Phase 8 예약 가드는 OPERATIONS 레지스터를 검사하고, **챕터 본문과 레지스터의 사실값 일치는 검사하지 않는다.** 자동검사 전체 PASS와 본문 날조는 양립한다.

## 5. 권고

1. **merge 절대 금지.** 브랜치는 증거 보존용으로 그대로 둔다 (push 자체는 잘한 일이다 — 덕분에 이 검수가 가능했다).
2. 건질 것과 버릴 것을 분리한다.
   * **건질 것**: `content_schema.json`, `test_validation.py`(11 tests), build.py 가드 일반화, QA 문서 체계, Nice 콘텐츠
   * **반려**: 04·05 본문 전체, 10의 유실분. 07–09는 검수 후 판정
3. 재작업 원칙은 하나다: **문장을 새로 쓰지 말고, main 원문에서 삭제·이동·링크 치환만 한다.** 사실값이 담긴 행(예약·시각·가격·전화·주소)은 글자 단위로 원문과 동일해야 하며, diff에서 사실값 행의 수정이 보이면 실패다.
4. 재작업 검증은 자동화한다: main과 재작업본 사이에서 확정 예약 토큰(확인번호·예약번호·가격·전화번호·시각) 전수 생존 검사를 스크립트로 수행한다. 이번에 사람의 "전수 대조했다" 보고를 신뢰할 수 없음이 확인됐기 때문이다.
