## 1. 최우선 — Day 번호 모순 규명 (BLOCKING)

Phase 4 완료 보고에 다음 모순이 있다.

> "데일리 카드 표준화 (**Days 1–7**)"
> "**Day 14** (Barcelona) 및 **Day 47** (Girona) 전 구간"

전체 일정은 43일이므로 **Day 47은 존재할 수 없다.** 또한 Nice가 Day 7–12, Provence·Lyon이 Day 12–26이므로 Barcelona가 Day 14일 수 없다.

### 수행할 일

1. `docs/RS_RESTRUCTURE_BASELINE_v1.0.md`에서 43일 일정의 **지역별 Day 배치 표**를 그대로 인용하라. 요약하거나 재계산하지 마라.
2. Barcelona 구간과 Girona·Bàscara 구간의 **실제 Day 번호 범위**를 확정하라.
3. 이번 Phase 4에서 **실제로 수정한 Daily 파일 전체 목록**을 파일 경로 그대로 제시하라.
4. 각 파일의 글로벌 Day 번호 · 로컬 Day 번호 · 날짜 · 요일이 기준선과 일치하는지 항목별로 대조하라.
5. 다음 중 어느 경우인지 판정하고 증거를 제시하라.
   * **(A) 보고서 표기 오류** — 파일은 정상. 정정된 범위를 제시한다.
   * **(B) 대상 외 Daily 수정** — Phase 4 범위 밖 파일을 건드렸다. 해당 diff를 전부 제시하고 **되돌린다.**
   * **(C) 기준선 자체의 모순** — 정본 간 날짜 충돌. 수정하지 말고 즉시 중단하고 보고한다.

**(B) 또는 (C)이면 이후 항목을 진행하지 말고 여기서 멈추고 보고하라.**

## 3. 미제출 매트릭스 제출

지시서 §5가 요구했으나 보고되지 않은 항목이다. 각각 표 형태로 제출하라.

### 3.1 일정·사실 보존 매트릭스
개편 대상 구간의 Day별로 **날짜 · 요일 · 숙박지 · 이동 · 예약 · 확정 방문지**를 기준선과 대조한 diff. 비의도 변경은 0건이어야 한다.

### 3.2 Place 필드 충족 매트릭스
개편 대상 장소 전체 × 11개 필드.

추천 이유 / 적정 체류시간 / 최적 방문시각 / 놓치지 말 것 / 관람순서 / 생략 가능 항목 / 예약·입장·교통 / 휴식·화장실 / 대안 / Daily·Walk·Map 링크 / 출처·검증 상태

충족률은 100%여야 한다. 미충족 항목은 장소명과 결측 필드를 명시하라.

### 3.3 Registry–Dossier 상호검증
* missing dossier / orphan dossier / duplicate ID 각각의 실측값
* Phase 4에서 **신규 등록한 place·walk ID 전체 목록**
* 신규 ID의 필수 필드·공식 출처 충족 여부

### 3.4 Barcelona 예약 매트릭스
장소 · 날짜 · 예약 입장시각 · 권장 도착시각 · 대기 여유 · 예약 실패 시 대안.

> 보고서에 "카녜테 식당, 렌터카 인수"가 "시각 지정 입장권" 항목으로 함께 묶여 있다. 성격이 다르므로 **입장권 예약 / 식사 예약 / 차량 인수 마감**을 분리하여 제시하라.

### 3.5 운전일 매트릭스
당일치기별 편도 운전시간 · 총 운전시간 · 주차 위치 · 주차 후 도보 · 출발 마감시각 · 일몰 시각 · 귀가 시각.

18:30 귀가 원칙이 각 운전일에 물리적으로 성립하는지 역산하여 검증하라.

### 3.6 Daily 삭제 순서
지시서 §3.2-9의 "늦었거나 피곤할 때의 삭제 순서"가 완료 보고에 언급되지 않았다. 대상 Daily 전체에 존재하는지 확인하고 결측을 보고하라.

## 4. 페이지 수 증분 규명

현재: **332 → 335 (+3)**

Phase 3B QA는 챕터를 `rs-region-v1`로 개편하면 "개별 분할 챕터 페이지로 전환"되며 페이지 수가 변동한다고 기록했다. 이번에 2개 챕터를 개편했는데 증분이 Walk 3개뿐이다.

### 확인할 일

1. 페이지 수 변동을 **유형별**로 분해하라. (Region 분할 페이지 / Daily / Place / Walk / 기타)
2. Barcelona·Girona 두 챕터가 Nice·Aix·Luberon·Avignon·Lyon과 **동일한 방식으로 분할 렌더링되고 있는지** 확인하라.
3. 분할되지 않았다면 그 원인을 규명하라. `CAT_RULES` 정규식이 두 챕터의 H2를 카테고리로 분류하지 못하고 있을 가능성이 있다.
4. 의도하지 않은 신규 페이지가 0건인지 확인하라.

## 6. 자동 이관의 표본 독해 검수

완료 보고의 "개별 관광지 묘사 구절들은 정본 장소 카드 형태로 **자동 이관 및 분리**되었으며"는 작업계획서 §1-7 "대량 자동 재작성 금지" 원칙과 충돌할 소지가 있다.

### 수행할 일

1. 이관에 사용한 방법(수작업 / 스크립트 / 혼합)을 명시하라. 스크립트를 사용했다면 그 코드를 첨부하라.
2. 다음을 **사람이 직접 읽고** 문맥 단절 · 기계적 요약 · 중복 · 내부 제작표현 · 판단 없는 나열을 검사하라.
   * Region 2개 전체
   * Daily 4개 이상 — **운전일 1개, 국경 이동일 1개, Barcelona 예약 밀집일 1개 반드시 포함**
   * Place 4개 이상 (자동 이관된 것 중에서 고를 것)
   * Walk 3개 전체
3. 발견한 결함은 숨기지 말고 전부 기록하라. 결함 0건 보고보다 정직한 결함 목록이 낫다.
