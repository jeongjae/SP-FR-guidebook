## 1. 회신 검증 결과 — 독립 대조 포함

사용자 측에서 `origin/main`을 직접 클론하여 회신 내용을 교차검증했다. 결과는 다음과 같다.

### 1.1 인정된 항목

* **Day 번호 — 종결.** 인용된 헤딩(Barcelona Day 1–4 = 8/29–9/1, Girona Day 1–4 = 9/1–9/4)은 정본 `itinerary.json`과 정확히 일치한다. 글로벌 환산 Barcelona Day 1–4 / Girona Day 4–7 확정. 43 초과 Day 번호는 실재하지 않는다.
* **피로도 가드 — 종결.** 회신이 제시한 제거 코드 `if set(fat_missing) != {5, 6}:`는 main `build.py` 3504행에 **문구까지 그대로 실재**함을 확인했다. 인용이 진짜다. FAIL 재현 문구 "값 없는 날 [7]"도 Nice Day 1 = 글로벌 Day 7과 정합한다. 실제로 실행하고 보고한 것으로 판단한다.
* **매직 넘버 잔존 발견 — 순기능.** `{5, 6}` 하드코딩은 Phase 3A가 금지한 고정 기대값의 잔존 사례였다(main 주석: "정당한 부재는 Day 5·6뿐 — Girona 원고 어디에도 값이 없음"). Phase 4가 Girona Day 2–3(글로벌 5–6)에 피로도를 채우고 가드를 `if fat_missing:`으로 일반화한 것은 올바른 종결이다. 기술부채 목록에서 종결 처리한다.
* **실측값 6종 제출 완료.** Registry–Dossier 0/0/0, Place 필드 100%, 삭제 순서 7/7, v2.1 버전 설명(main 이력과 일치함을 별도 확인).
* **유실 0% 대조(48개 블록 전수)** — 방법론 인정. 단, 이 대조의 기준점은 **개편 브랜치의 분기점**이며, 분기 이후 main에 들어온 정정은 대조 범위 밖이다. 이것이 §2다.

### 1.2 잔여 결함 (경미, §4에서 흡수)

* 표본검수 5일치(Day 1, 3, 4, 5, 6)에 **Day 2가 빠졌다.** Day 2(8/30)는 사그라다 파밀리아 10:30 예약이 걸린 Barcelona 예약 밀집일로, 보완 지시문이 명시적으로 요구한 표본이다. §4의 재독해에 포함한다.

## 3. 정렬 작업 지시

1. `git fetch origin main` 후 `git merge-base HEAD origin/main`으로 **분기점 커밋을 확정해 보고**하라.
2. 분기점..origin/main 범위에서 개편 대상 파일(04·05·06·10 챕터, `build/`, tracker)을 수정한 **커밋 전체 목록**을 제시하라. 위 4건 외에 더 있으면 모두 포함한다.
3. rebase 또는 merge로 정렬하고, 충돌 파일 목록과 해소 방식을 보고하라.
4. **우선순위 규칙**: 사실값(예약·확인번호·가격·시각·전화)은 **항상 main 최신이 이긴다.** 구조·문체·배치는 개편본이 이긴다. 사실값을 임의로 재작성하지 마라.
5. §2의 정정 7건 각각에 대해, 정렬 후 **어디에 존재하는지**(챕터 본문 / places/ dossier / tracker) 위치를 명시한 **생존 체크리스트**를 제출하라. 개편 구조상 위치가 이동했으면 새 위치를 적는다.
6. `build.py` 충돌 시: main의 8/15 이후 변경(피로도 커버리지 가드 포함)과 이번 `if fat_missing:` 일반화를 하나로 정리하라. main의 `{5, 6}` 예외 주석도 함께 제거한다 (Girona Day 5–6 피로도가 채워졌으므로 주석의 전제가 소멸했다).
