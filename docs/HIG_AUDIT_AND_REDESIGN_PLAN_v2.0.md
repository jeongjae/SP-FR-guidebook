## 1-1. 🔴 유니코드 도형 402회 — 빌드와 CSS 가 직접 찍어낸다

`CLAUDE.md` 는 명시적으로 금지한다:

**장소는 이 가이드북의 최소 단위다.** 그 등급 신호를, 규칙이 금지한 방식으로

| | |
|---|---|

## 1-3. 🟡 근거 — 번들 폰트가 이 기호들을 안 덮는다

`style.css` 의 나눔고딕 `unicode-range` 는 2000번대에서 다음만 커버한다:

```
U+2000-206F, U+2122, U+2191(↑), U+2193(↓), U+2212(−)
```

즉 위/아래 화살표와 뺄셈기호는 **덮이고**, 실제로 많이 쓰는
`←(U+2190) →(U+2192) ■(U+25A0) ●(U+25CF) ○(U+25CB) ◇(U+25C7) ▨(U+25A8)
◈(U+25C8) ★(U+2605) ⚠(U+26A0) ─(U+2500)대 🗺(U+1F5FA)` 는 **전부 범위 밖**이라
시스템 폰트 폴백으로 넘어간다. 오프라인 PWA 로 저장한 기기에서 폴백 커버리지가
없으면 그 자리가 □ 가 된다. `CLAUDE.md` 가 경고한 정확히 그 시나리오다.

## 이 진단이 확인하지 않은 것

기계 검사는 **터치타깃·글자크기·명암비·안전영역·리플로·뷰포트** 여섯 가지만 본다.
위 26건은 전부 실제 렌더 계측과 소스 대조로 확인했지만, 명료함·경의·깊이 같은
원칙 자체가 충족됐는지는 **여전히 사람이 판단해야 한다.** 이 문서를 근거로
"HIG 를 만족한다"고 말하지 않는다 — 검사한 항목만 보고한다.

또한 **기호가 실제 기기에서 두부가 되는지는 이 환경에서 확인할 수 없다.**
확인한 것은 번들 폰트의 `unicode-range` 가 그 문자들을 덮지 않아 시스템 폰트
폴백에 의존한다는 사실까지다. 위험의 크기는 실제 기기(특히 오프라인 저장 상태의
iOS/Android)에서 한 번 확인하는 편이 낫다.
