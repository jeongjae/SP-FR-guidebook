## 1. 목표

Phase 2에서 검증하고 Phase 3B에서 4개 지역에 적용한 `rs-region-v1` 구조를 Barcelona와 Girona·Bàscara 권역에 확대한다.

1. 두 Region 챕터를 `content_schema: rs-region-v1` 14개 H2 규격으로 재편한다.
2. 반복되는 개별 장소 서술을 정본 장소 카드(Place Dossier)로 이관하고, Region·Daily에는 **판단·요약·링크만** 남긴다.
3. 해당 구간 Daily를 Nice Pilot 데일리 카드 규격으로 표준화한다.
4. Barcelona 예약 관광지의 **날짜·입장시각·도착 여유시간**을 실행 가능한 수준으로 명시한다.
5. Bàscara 거점에서 출발하는 국경 이동 당일치기(Collioure 등)와 Empordà 마을 루트의 **운전·주차·귀가 실행정보**를 확정한다.
6. Walk 3개를 신규 제작하거나 규격에 맞게 재편한다.

**정보를 추가해 분량을 늘리는 작업이 아니다.** 중복 제거·재배치·편집 판단 강화가 핵심이다.

## 3. 변경사항

### 3.1 Region 챕터

1. front matter에 `content_schema: rs-region-v1`을 선언한다.
2. 본문을 아래 14개 H2 순서로 재배치한다. 순서 변경·중복·누락은 빌드 실패 사유다.

   1. `## Editor's Verdict — 이 지역에 시간을 쓸 가치와 한계`
   2. `## 꼭 경험할 세 장면`
   3. `## 생략해도 되는 것`
   4. `## 한눈에 보기 — 우선순위·권역·소요시간`
   5. `## 여행 전체에서의 역할`
   6. `## 추천 체류 리듬`
   7. `## 구역별 이해와 숙소 생활권`
   8. `## 도착·출발·지역 내 교통`
   9. `## 핵심 셀프가이드`
   10. `## 음식·시장·카페·생활체험`
   11. `## 당일치기·우천·피로 대안`
   12. `## 예약·비용·안전·주차·귀가`
   13. `## 공식 확인 정보와 재확인 대상`
   14. `## 검증 상태 — 보강본 근거`
3. Region에서 **날짜별 전체 시간표를 제거**하고 해당 Daily로 연결한다.
4. 개별 장소의 정체성·선정 이유·관람 포인트 서술은 Place Dossier로 이관하고, Region에는 한 줄 판단과 링크만 남긴다.
5. 다음 내부 제작 흔적을 독자 화면에서 제거한다.
   * `Commercial Guide Module`, `Phase N`, `P0 연결` 등 제작 용어
   * `VISUAL:*`, `status=pre-publication` 등 자리표시자
   * "기존 원고가…", "저장소 자료가…" 같은 작성 과정 서술
   * 취소·폐기된 계획과 이전 후보 기록
   * 독자가 행동으로 옮길 수 없는 검증 과정 설명

### 3.2 Daily 카드

대상 구간의 모든 Daily를 Nice Pilot 규격으로 맞춘다.

1. 오늘의 결론 한 문장
2. 상태 배지 — `{{badge:fixed|고정}}` 또는 `{{badge:conditional|조건부}}`
3. 피로도 수치 (1/5 ~ 5/5)
4. 첫 행동·첫 예약·마지막 귀가 시각
5. 핵심 행동 **최대 3개**, 방문지 **최대 5개**
6. 시간표 — `| 시간 | 일정 | 실행 포인트 |` 형식, 이동·식사·휴식 포함
7. 오늘 지도
8. 식사와 카페
9. 늦었거나 피곤할 때의 **삭제 순서**
10. 우천·휴관·교통장애 대안
11. 장소 상세 링크

로컬 Day 번호와 글로벌 Day 번호, 날짜, 요일의 정합성을 `normalize_day_headings` 기준으로 검사한다.

### 3.3 Barcelona 고유 요구사항

1. **예약 관광지**: 시각 지정 입장권이 필요한 장소마다 다음을 명시한다.
   * 방문 날짜와 예약 입장시각
   * 권장 도착 시각과 보안검색·입장 대기 여유
   * 예약 실패 시 대안과 그날 일정의 재배치 순서
2. **권역별 묶음**: 하루에 서로 다른 권역을 왕복하지 않도록 방문지를 지리적으로 묶고, 묶음 간 이동수단·소요시간을 명시한다.
3. **혼잡·소매치기**: 관광 밀집 구역의 시간대별 혼잡과 실제 대응 행동을 실무 정보로 기술한다. 일반적 경고 문구는 쓰지 않는다.
4. **식사 시간대 차이**: 스페인의 늦은 점심·저녁 시각이 시간표와 충돌하지 않는지 확인한다.

### 3.4 Girona·Bàscara·Empordà 고유 요구사항

1. **거점형 운전 일정**: Bàscara 숙소를 기준으로 각 당일치기의 편도 운전시간, 총 운전시간, 휴식 지점을 명시한다.
2. **주차**: 운전하는 모든 날에 주차 위치, 주차 후 도보시간, 차량 회수 계획, 출발 마감시각을 둔다.
3. **국경 이동 당일치기** (Collioure 등 프랑스 방면)
   * 국경 통과 소요시간과 톨·주유 계획
   * 렌터카 국경 통과 관련 확인 항목 (계약 조건은 `REVERIFY`로 표시하고 임의 단정하지 마라)
   * 일몰 시각과 야간 귀가 조건
   * 통신·데이터 로밍 변화 여부
4. **마을 간 선택 규칙**: Cadaqués·Empordà 마을은 유사한 경험이 반복되므로, 무엇을 고르고 무엇을 버릴지의 판단 기준을 Region에 한 번만 쓰고 Daily에서 반복하지 않는다.
5. **시장·휴관 요일**: 마을 시장 요일, 박물관 휴관일, 식당 휴무일이 실제 방문 요일과 충돌하지 않는지 대조한다.

### 3.5 Walk 3개

각 Walk는 다음을 모두 갖춘다.

* 한 줄 성격과 추천 대상
* 시작점·종료점·거리·순수 보행시간·권장 총시간
* 최적 시간대와 피해야 할 시간
* **8–15개 정차점**: 이동 지시 → 보는 방향 → 관찰 포인트 → 짧은 의미
* 카페·벤치·화장실·시장 등 휴식 지점
* 중간 이탈점과 축소 루트
* 계단·경사·노면·혼잡·치안
* 본문과 번호·순서가 완전히 일치하는 지도
* Google Maps 및 오프라인 사용법

### 3.6 사실정보 취급

1. 운영시간·가격 등 변동정보를 이번 단계에서 임의로 갱신하지 마라.
2. 의심되거나 충돌하는 정보는 `REVERIFY`로 분류하고 근거·영향을 QA 보고서에 기록한다.
3. 일정, 날짜, 숙박일수, 예약 상태, 확정 방문지는 사용자 승인 없이 변경하지 마라.

### 4.2 감량률 측정법 — 필독

Phase 3B QA는 **파일 전체 크기**를 기준으로 68~74%를 보고했다. 이 값은 Phase 2가 정의한 측정법과 다르다. Phase 4에서는 다음을 지킨다.

1. 감량률은 **front matter, 코드 블록, 링크 목록을 제외한 독자용 본문 글자수** 기준으로 before/after를 동일하게 측정한다.
2. 같은 측정법으로 **Nice와 Phase 3B 4개 지역의 값도 재산출하여 비교표에 함께 제시한다.** 측정법 차이로 인한 수치 불일치를 QA 보고서에서 해소한다.
3. 합격 기준은 **30–45%** 대역이다.
4. 측정 결과가 45%를 넘으면 자동 실패로 처리하지 말고, 다음을 모두 제출한 뒤 **사용자 승인을 받는다.**
   * 초과분이 어느 콘텐츠의 어디로 이관되었는지 보여주는 이관 매트릭스
   * 핵심 사실·편집 판단·실무정보 유실 0건 증빙
   * 초과 사유 (예: Place Dossier 이관량이 예상보다 큼)
5. 측정 결과가 30% 미만이면 중복 제거가 불충분한 것이다. 재작업한다.

### 4.3 자동검사

다음을 모두 실행하고 전부 PASS해야 한다.

```
python3 build/build.py
python3 build/test_validation.py
python3 build/hig_check.py
```

추가로 content quality, PWA, broken-link 검사를 실행한다.

* **코드 수정 없이 통과**해야 한다. `build.py`에 지역별 조건문이나 기대 숫자를 추가했다면 이는 기준 미달이다.
* Phase 3A의 9개 네거티브 fixture가 여전히 예상대로 FAIL하는지 확인한다.
* Phase 2에서 지적된 `rewrite_asset_links` 회귀 검사를 다시 실행하여, 이번 변경이 개편 대상 외 페이지의 상대링크를 바꾸지 않았는지 확인한다.
* HTML 페이지 수 변동을 **페이지 유형별로** 설명한다. 기준값 332개 대비 증감분에 의도하지 않은 페이지가 없어야 한다.

## 6. 중단 조건

다음 중 하나가 발생하면 **추측하여 진행하지 말고** 증거·영향·선택지·권고안을 보고하라.

* 선행 Phase 결과가 PASS가 아니거나 필수 산출물이 없음
* 기존 미커밋 변경과 작업 범위가 충돌함
* 확정 일정과 정본 사이에 날짜·숙박·이동 모순이 발견됨
* 검증 통과를 위해 `build.py`에 지역명 의존 조건문이나 기대 숫자를 추가해야 함
* 헤딩 변경이 장소 추출·앵커·리다이렉트를 안전하게 유지할 수 없게 함
* 감량 과정에서 핵심 사실이나 실행정보가 유실됨
* 감량률이 30–45% 대역을 벗어나며 그 사유를 이관 매트릭스로 설명할 수 없음
* 지도와 Walk를 신뢰할 수 있게 연결할 수 없음
* 예약 관광지의 입장시각과 일정이 물리적으로 양립 불가능함
* 국경 이동 당일치기의 총 운전시간이 계획 원칙을 초과함
* 빌드 또는 PWA 회귀를 최소 변경으로 해결할 수 없음
