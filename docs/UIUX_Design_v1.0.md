# 가이드북 웹사이트 UI/UX 설계 v1.0

## 1. 콘텐츠 구조 분석

리더 에디션 11챕터를 검토한 결과, 콘텐츠는 다음 구조를 가진다.

### 챕터 유형

| 유형 | 챕터 | 성격 |
|---|---|---|
| 안내 | 01 사용법 · 02 하이라이트 | 여행 전 1회 정독 |
| 일정 기준 | 03 Master Itinerary | 43일 전체 기준표, 반복 참조 |
| 지역 가이드 | 04~11 (8개 지역) | 본문의 중심, 3층 Layer 구조 |

### 지역 챕터의 공통 3층 구조

- **Layer 1 실행** — 한눈에 보는 실행 요약, 날짜별 확정 일정, Day별 상세 실행표, 피로도
- **Layer 2 이해** — 지역을 읽는 열쇠, 동네·숙소 생활권, 추천등급, 방문지 상세
- **Layer 3 실용** — 숙소·레스토랑·시장·운동·행사·교통·우천 대체안·예약카드·확인목록

Day별 섹션 보유: 05, 06, 08, 09, 10, 11 (총 41개 Day 섹션).
04·07은 날짜별 일정표만 보유.

### 교차 참조 관계

- 지역 챕터 06 ↔ Nice 실행지도, 10 ↔ Lyon·Annecy 실행지도
- 모든 지역 챕터 ↔ 트래커(일정·예약·이동·숙소)

## 2. 이용 시나리오 (페르소나 모드)

| 모드 | 시기 | 핵심 질문 | 주 사용 콘텐츠 |
|---|---|---|---|
| **계획 모드** | 여행 전 | "이 지역은 어떤 곳이고 뭘 예약해야 하나" | Layer 2·3, 트래커, 예약카드 |
| **실행 모드** | 여행 중 | "오늘 어디서 뭘 하지" | 해당 날짜 Day 섹션, 지도, 우천 대체안 |

설계 원칙: **실행 모드는 2탭 이내 도달**(오늘 버튼), 계획 모드는 구조적 탐색(타임라인·Layer 점프)을 제공한다.

## 3. 정보 구조 (IA)

```
홈 = 여정 타임라인
├─ 시작하기 · · · · 01 사용법 / 02 하이라이트 / 03 전체일정
├─ 지역 8개(여정 순) 04 Barcelona → … → 11 Paris
│    └─ 챕터 내부:   지역소개/일정/여행정보/먹거리/교통/숙박/예약/경비/여행팁/부록 + Day 점프
├─ 실행지도 · · · · Nice / Lyon·Annecy
└─ 트래커 · · · · · 일정 / 예약 / 이동 / 숙소 / 대시보드
```

## 4. 내비게이션 체계 (3레벨)

### 전역 (모든 페이지)

- **상단바**: ☰ 메뉴(드로어) · 현재 위치 제목 · [PC 전용] 일정 / 지도 / 트래커 바로가기
- **드로어 메뉴**: 검색창 + 전체 챕터 목록(날짜 표시) + 지도·트래커
- **모바일 하단 탭바**(5개, 엄지 도달권): 홈 · 일정 · **오늘** · 지도 · 트래커

### 챕터 수준 (지역 챕터)

- **sticky 서브내비**: 카테고리 점프 + `9/4 · 9/5 …` Day 칩 (가로 스크롤)
- **카테고리 재분류(v1.1)**: 원문의 Layer 1·2·3 구조를 빌드 시 h2 섹션 단위로 재분류해
  `지역소개 / 일정 / 여행정보 / 먹거리 / 교통 / 숙박 / 예약 / 경비 / 여행팁 / 부록` 10개
  카테고리로 재배치한다. 소스는 수정하지 않으며(상류 콘텐츠 워크플로 관리),
  키워드 규칙 + 챕터별 예외표로 매핑하고 미분류 섹션은 빌드 실패로 처리한다.
  경비 섹션이 없는 챕터에는 트래커 안내 스텁을 넣어 메뉴를 일관되게 유지한다.
- **주요 방문지 카드**: 여행정보 카테고리 첫머리에 실행지도 기준점 기반 장소 카드
  (한 줄 소개 + Google Maps·실행지도 링크). 사진은 열람 시 브라우저가 Wikipedia
  REST API에서 불러오는 점진적 향상 방식 — 오프라인·실패 시 자동 숨김.
- **관련 리소스 카드**(본문 상단): 해당 지역 실행지도, 예약 현황, 43일 일정표
- **이전/다음 지역** 페이저 (여정 순서)

### 페이지 내부

- 접이식 목차(전체 섹션), 맨 위로 버튼

## 5. 핵심 UX 장치

1. **'오늘' 버튼** — 빌드 시 43일 전체의 `날짜 → 챕터#Day섹션` 매핑을 생성해 내장.
   여행 기간 중이면 오늘의 Day 섹션으로 직행, 기간 밖이면 전체 일정표로 이동.
   시간대는 현지(Europe/Paris) 기준.
2. **여정 타임라인 홈** — 8개 지역을 날짜·박수와 함께 세로 타임라인으로 시각화.
   각 정거장에서 가이드·지도로 바로 진입.
3. **검색** — 빌드 시 챕터·섹션 제목 인덱스(약 300항목)를 생성, 드로어에서 즉시 필터링.
   fetch 불가 환경(file://)을 위해 JSON이 아닌 JS 전역변수로 내장.
4. **Layer 시각 구분** — Layer 경계 h1에 배지·구분선을 넣어 3층 구조를 스캔 가능하게.
5. **오프라인 우선** — 외부 의존 없음 유지. JS 미동작 시에도 모든 콘텐츠·링크 열람 가능
   (점진적 향상: 드로어·오늘·검색만 JS).

## 6. 반응형 규칙

| 뷰포트 | 상단바 | 하단 탭바 | 서브내비 | 본문 |
|---|---|---|---|---|
| 모바일 < 768px | ☰ + 제목 | 표시 (5탭) | 가로 스크롤 칩 | 1열, 표 가로스크롤 |
| PC ≥ 768px | ☰ + 제목 + 바로가기 | 숨김 | 칩 전체 표시 | 최대 46rem 중앙 |

다크모드는 시스템 설정(`prefers-color-scheme`) 자동 적용.

## 7. 구현 구성

- `build/build.py` — Day 섹션·Layer 앵커 추출, 날짜 매핑·검색 인덱스 생성, 페이지 셸 렌더링
- `build/assets/style.css` — 위 체계의 스타일
- `build/assets/nav.js` — 드로어·오늘 버튼·검색·맨위로 (콘텐츠 데이터는 `data.js`로 빌드 시 생성)
