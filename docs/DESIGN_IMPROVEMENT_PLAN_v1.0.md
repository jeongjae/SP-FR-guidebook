# 디자인 개선 계획 · 시안 명세 v1.0

2026-08-13 · 근거: `HIG_AUDIT_AND_REDESIGN_PLAN_v2.0.md`
시안: `docs/previews/design-mockup-v1.0.html` (라이트·다크 렌더 확인)

이 문서는 진단(무엇이 문제인가)을 **구체적 디자인 결정**(무엇으로 바꾸는가)으로
옮긴다. 실행 순서·빌드 가드는 v2.0 이 정본이고, 여기서는 **각 요소가 실제로
어떤 모양·토큰·규칙을 갖는지**만 확정한다.

## 설계 원칙 — 이 프로젝트에 이미 있는 것

새 디자인 언어를 들이지 않는다. `CLAUDE.md` 와 `style.css v3.0` 이 정한 것을 따른다.

| 축 | 정본 | 이 계획이 지키는 것 |
|---|---|---|
| 색 | 스페인·프랑스 국기 팔레트 | 국기 원색은 면에만, 글자는 `--sig-*-ink` |
| 명암 | 본문 7:1 · 크롬 4.5:1 | 시안 전부 이 하한 위에서 그렸다 |
| 아이콘 | `icons.py` → CSS 마스크 | 새 아이콘도 같은 파이프라인, 페이지 무게 0 |
| 신호 | 색만으로 정보 전달 금지 | 등급은 색 + **모양**으로 이중 부호화 |
| 타이포 | HIG 스케일 토큰 | 하드코딩 대신 토큰에 묶는다 |

**시안은 제안이지 소스가 아니다.** `docs/previews/` 에만 있고 `site/` 를 건드리지 않는다.

## 시안 A — 아이콘

### A-1. 등급 마커 5종: 유니코드 도형 → CSS 마스크

현행은 `.grade-*::before` 가 `content:"■"` 처럼 유니코드 도형을 찍는다(322회).
`icons.py` 에 5종을 추가하고 마스크로 바꾼다. **모양 언어를 그대로 유지**한다 —
채움=중요, 외곽선=보조, 사선=회피. 색맹 대비가 색이 아니라 모양에 실려 있어야 한다.

| 슬러그 | 라벨(KO/EN) | 색 토큰 | 현행 | 제안 SVG (viewBox 0 0 24 24) |
|---|---|---|---|---|
| essential | 필수 / Must | `--sig-critical-ink` | ■ | 채운 마름모 `M12 2.6 21.4 12 12 21.4 2.6 12Z` (fill) |
| priority | 우선 추천 / Recommended | `--accent` | ● | 채운 원 `r=7.6` (fill) |
| optional | 선택 / Optional | `--text-2` | ○ | 링 `r=7` stroke 2.4 |
| alternative | 대체 / Backup | `--sig-caution-ink` | ◇ | 마름모 외곽선 stroke 2.2 |
| excluded | 비추천 / Skip First | `--muted` | ▨ | 원+사선 (금지 기호) stroke 2.2 |

- 크기: 본문에서 `0.9em` (현행 `.grade::before` 와 동일 비율)
- 색: `currentColor` — `.grade-*` 가 이미 정하는 색을 그대로 받는다
- 접근성: `aria-hidden="true"`, 라벨 텍스트가 실제 의미를 전달 (지금도 병기됨)

### A-2. 하단탭 아이콘 — 겹치는 은유 3개 분리

현행 5탭 중 **오늘·지도·가이드가 모두 원/핀 계열**이라 20px 에서 안 갈린다.
셋을 서로 다른 실루엣으로 만든다. 나머지(일정=선, 준비=사각)는 그대로 둔다.

| 탭 | 현행 문제 | 제안 | 실루엣 |
|---|---|---|---|
| 오늘 | (유지) | 링 + 중심 점 | 원 계열 |
| 일정 | — | 가로 3선 | 선 |
| 지도 | 나침반으로 읽힘 | **접힌 지도** | 면 |
| 가이드 | 장소 핀과 동일 | **나침반**(링+바늘) | 방사 |
| 준비 | — | 체크박스 | 사각 |

- `지도` 접힌 지도: `M3 6.2 9 3.8l6 2.4 6-2.4v13.6l-6 2.4-6-2.4-6 2.4Z` + 세로 접선 2개
- `가이드` 나침반: 링 `r=8.4` + 채운 바늘 마름모. 장소 핀(`ic-pin`)은 본문 전용으로 남아 충돌이 사라진다
- 은유 교체 별건(본문 아이콘): `flag`(=비상, 국기와 충돌) → `alert`, `music`(=공연, 실데이터는 오페라·발레·연극) → `stage`

## 시안 B — 등급 마커가 실제로 붙는 자리

`places/index.html` 94개 장소가 등급으로 정렬·구분된다. A-1 의 마커를 장소 목록 행

A-1 을 끝내면 여기서 두부 위험이 사라진다.

## 시안 C — 표 → 카드 (검증된 패턴 재사용)

예약 현황에서 이미 구현·검증한 `.rz-*` 카드 패턴을 나머지 시트에 적용한다.
**새 컴포넌트가 아니다** — 같은 CSS 를 슬러그만 바꿔 쓴다.

| 시트 | 열×행 | 390px 넘침 | 카드 앞면에 세울 값 |
|---|---|---|---|
| accommodation | 20×8 | +1857px | 거점 · 박수 · 상태 · 예약목표일 |
| transport | 18×10 | +1235px | 구간 · 일시 · 수단 · 상태 |
| locks | 7×20 | +549px | 항목 · 잠금상태 · 필요 입력 |
| itinerary | 20×43 | +2500px | (부록으로 강등 — 시안 없음, v2.0 4-1 참조) |

카드 규칙(예약 현황과 동일):
- 좌측 4px 상태색 띠, 앞면 3~4행 + `<details>` 뒷면
- 날짜가 여행 43일 안이면 그 날 데일리 카드로 링크
- 도구 막대(검색+상태칩+정렬) 상단바 아래 고정
- 금액 0·빈칸은 '없음'으로 (미입력을 0원 확정처럼 보이지 않게)

## 시안 D — ASCII 의사결정 트리 → 중첩 목록

`<pre>` 고정폭 트리 18개가 390px 에서 잘려 **결론(어느 숙소인가)이 화면 밖**이다.
중첩 `<ul>` 로 바꾸면 폭에 맞춰 접히고 기호(─├└│)도 사라진다(시안 E 폰트 문제도 함께 해소).

- 분기 질문 = `.q` 볼드, 예/아니오 = `.yes`(steady)/`.no`(muted)
- **결론 = 캡슐** `.res` (`--accent-soft` 바탕) — 가장 중요한 정보를 시각적으로 고정
- 들여쓰기는 왼쪽 연결선(`::before`/`::after`)으로, 공백 정렬에 기대지 않는다

이 변환은 원고(`source/**.md`)의 코드블록을 손봐야 한다 — 빌드 매핑이 아니라 원고 편집이다.

## 시안 E — 별점 ★★★★★ → 막대 + 숫자

별점은 기호가 곧 값이라 두부가 되면 평가가 통째로 사라진다. 피로도(`.fatigue`)에
**이미 있는** 막대+숫자 컴포넌트로 통일한다.

- 5칸 막대(채움 = `--sig-caution`) + 숫자 `5.0` + 라벨
- 색 빼도 채운 칸 수로 판독 (피로도와 동일 원리)
- 원고의 `★★★★★` 를 이 마크업으로 치환

## 신설 아이콘·컴포넌트 요약

`icons.py` 추가: `grade-essential/priority/optional/alternative/excluded`(5),
`map`(교체), `region`(교체), `alert`, `stage`. → 정의 총 33 + 7 = 40, 미사용 `photo`·`filter` 는 정리.

`style.css` 변경:
- `.grade-*::before` 를 `content` → `mask` 로 (마스크 변수는 `icons.css()` 가 생성)
- `.rz-*` 카드 패턴을 accommodation/transport/locks 슬러그에 재사용
- `.tree`(의사결정), `.rate`(별점) 컴포넌트 신설
- 미정의 토큰(`--shadow-1` 등 4종) 정의 또는 제거


**글리프 가드**(unicode-range 밖 문자), **토큰 가드**(미정의 `var()`),
**리플로 가드**(table·pre 390px 넘침).

### 이 시안이 확인하지 않은 것

시안은 프로젝트 실제 토큰 위에서 라이트·다크 양쪽으로 렌더해 명암·모양을
확인했다. 그러나 **실제 기기에서 기호가 두부가 되는지, 새 아이콘이 오프라인
저장 상태에서 어떻게 보이는지는 이 환경에서 확인할 수 없다.** 소스 반영 전
실기(특히 iOS/Android PWA 저장본)에서 한 번 확인하는 편이 낫다.
새 아이콘의 은유가 맞는지도 사람의 판단이 필요하다 — 시안은 후보이지 결정이 아니다.
