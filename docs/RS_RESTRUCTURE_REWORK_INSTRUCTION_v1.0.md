## 1. 절대 원칙 — 편집이지 생성이 아니다

이번 사고의 원인은 원문을 참조한 **재생성**이었다. 재작업에서 허용되는 조작은 다음 네 가지뿐이다.

1. **블록 삭제** — 중복·내부 제작표현·폐기안 (처분 근거는 DUPLICATION_MAP 기준)
2. **블록 이동** — 잘라내기-붙여넣기. 이동 중 문장 수정 금지
3. **헤딩 삽입·치환** — rs-region-v1 14개 H2 골격 구성용
4. **연결문 최소 신규 작성** — 문단당 1문장 이내, **사실값(시각·가격·번호·지명·상태) 포함 금지**

금지:
* 원문 문장을 "요약"하거나 "다듬어" 다시 쓰는 행위 전면 금지
* 예약 상태 단정 표현("예약 완료", "예매 완료") 신규 작성 금지 — 원문에 있는 상태 표현을 그대로 옮기는 것만 허용
* main 원고에 없는 피로도·시간표·거리·소요시간 값 창작 금지

기계적 판별 기준 (검수 시 실제로 적용된다):
* 사실값이 담긴 행은 main 원문과 **글자 단위 일치**해야 한다
* main 원고의 독자용 본문에는 습니다체가 **0건**이다. 재작업본도 **0건**이어야 한다. 습니다체 검출 = 재생성 판정

## 2. R1 — 확정 사실 토큰 생존 가드 신설 (콘텐츠 작업 전 선행)

### 2.1 설계

`build.py`에 다음 가드를 추가한다 (지역명·고정 개수 하드코딩 금지 — Phase 3A 원칙 유지).

1. **토큰 추출원**: `source/OPERATIONS/110_Phase8_Reservation_and_Operations_Lock_Register_v1.0.md`의 확정(`확정`/`CONFIRMED`) 레코드에서:
   * 예약·확인번호 (영숫자 코드)
   * 전화번호 (`+33`/`+34` 패턴)
   * 결제·보증금 금액 (확정 표기된 것)
2. **생존 조건**: 각 토큰이 **독자 정본 최소 1곳**에 존재해야 한다 — 대상: `20_Regional_Chapters/`, `10_Core/`, `ASSETS/90·91`, `data/daily-cards/`.
3. 실패 시 빌드 중단, 누락 토큰과 출처 레코드를 출력한다.
4. 예외는 레지스터 레코드 단위의 명시적 표시(예: `guard: operations-only`)로만 허용하고, 예외 목록을 빌드 로그에 출력한다.

### 2.2 검증

* **네거티브 fixture 추가**: 챕터에서 확정 토큰 1개를 제거하면 빌드가 FAIL하는 테스트를 `test_validation.py`에 12번째로 추가
* main 그대로에서 가드 PASS 확인 (main은 완전 정본이므로 통과해야 정상. 통과하지 못하면 그 자체가 발견이다 — 수정하지 말고 목록 보고)
* 가드 코드에 지역명·고정 숫자가 없음을 확인

**R1 완료 시 커밋·push 후 보고. 검수 통과 전 R2로 진행하지 마라.**
