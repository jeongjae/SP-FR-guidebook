# 일자 축 단일화 · 대시보드 재구성 · 축 이름 통일 — 종합 진단과 개선안 v1.0

2026-08-15 · 근거: HIG 통합 진단 v2.0 의 4-1 · 2-3 · 4-6 (남은 🔴 2건 + 🟡 1건)
측정: origin/main(#132) 기준 실빌드 · 링크 그래프는 상대경로 해석 포함 재계산

이 문서는 사용자 결정이 필요한 마지막 세 항목의 **현재 상태를 실측**하고,
선택지와 **권고안**을 낸다. 셋은 서로 얽혀 있다 — 일자 축의 뿌리를 정해야
이름이 정해지고, 시트 일정표의 강등 여부가 대시보드 재구성과 함께 트래커

## 1. 일자 축 단일화 (진단 4-1, 🔴)

### 실측 — 세 페이지의 실체

| 페이지 | 본문 | 담는 것 | 인바운드 링크 |
|---|---|---|---|
| `chapters/itinerary.html` | 5,964자 · 링크 88 | 하루 1카드: 핵심 요약 + **피로도 + 잠금 + 선택·축소** | **280개** (사이트 전역) |
| `daily/index.html` | 2,359자 · 카드 43 | 지역별 그리드: 날짜·거점·한 줄 요약 | **272개** (사이트 전역) |
| `tracker/itinerary.html` | 9,068자 · 표 1 | 시트 원본 20열 (도보시간·숙박차수 등) | **7개 — 전부 tracker/ 내부** |

세 가지 사실이 결정을 좌우한다.

**① `tracker/itinerary.html` 은 이미 고립돼 있다.** 인바운드 7개가 전부
트래커 탭 스트립과 트래커 색인이다 — 사이트의 다른 어디서도 링크하지 않는다.
부록으로 내려도 끊기는 길이 없다 (CLAUDE.md 링크 그래프 원칙으로 확인).

**② 나머지 두 페이지는 둘 다 대형 허브다.** 280 vs 272 — 어느 쪽도 조용히
리다이렉트할 수 없고, 할 필요도 없다(빌드가 링크를 다시 쓰므로). 관건은
콘텐츠다: 두 페이지는 **같은 43일을 다른 밀도로** 보여준다. 상세(피로도·
잠금·선택축소)는 `chapters/itinerary` 에만 있고, 지역별 조망은 `daily/index`
에만 있다.

**③ 축 위치가 어긋나 있다.** 일자 축의 원자(day-NN)는 `daily/` 에 살고,
좌표 바의 '일자' 셀도 `daily/index.html` 을 가리킨다. 그런데 하단탭 '일정'은
`chapters/itinerary.html` — **지역 축의 디렉터리** 안에 있는 페이지로 간다.
과거 사고(챕터/데일리 이중화)가 정확히 이 방향의 흐림에서 시작됐다.

### 선택지

| | 안 | 장점 | 단점 |
|---|---|---|---|
| A | `chapters/itinerary` 를 뿌리로, `daily/index` → 리다이렉트 | 상세 정보가 이미 있는 쪽 유지 | 일자 축 뿌리가 지역 디렉터리에 남는 구조 모순 지속 |
| **B (권고)** | **`daily/index` 를 뿌리로 통합** — `chapters/itinerary` 의 하루 요약(피로도·잠금·선택축소)을 `daily/index` 카드에 흡수, `chapters/itinerary` → 리다이렉트 | 축과 URL 이 일치(`daily/` = 일자 축의 집), 밀도 두 벌이 한 페이지로, 과거 사고 구조의 잔재 청산 | 흡수 작업량 (빌드 한 곳 — day 카드 생성부에 요약 필드 추가) |
| C | 두 페이지 유지 + 상호 링크 강화 | 작업 없음 | 진단 4-1 미해결 — "같은 43일, 두 목록" 지속 |

**권고 — B.** 근거: (i) CLAUDE.md "하나의 것은 하나의 페이지에만" — 43일
목록이라는 하나의 것이 두 페이지다. (ii) 원자가 사는 곳이 축의 집이다 —
day-NN 이 `daily/` 에 있으니 뿌리도 `daily/` 다. (iii) 하단탭 활성 규칙(#126)
이 이미 `daily/* → 일정 탭` 으로 잡혀 있어, 탭 목적지만 `daily/index.html` 로
바꾸면 모순이 사라진다.

B 의 실행 요강:
- `daily/index` 의 각 날 카드에 `chapters/itinerary` 가 갖던 요약 줄(핵심·
  피로도·잠금) 추가 — 소스는 동일(원고·itinerary.json)하므로 사본이 아니라
  같은 정본의 한 렌더가 된다
- `chapters/itinerary.html` → `daily/index.html` 리다이렉트 (기존 리다이렉트
  스텁 패턴 재사용, 앵커 `#day-NN` 보존)
- 하단탭 '일정'·홈 액션·regions 관련 링크의 목적지 교체 (빌드 상수 2곳)
- `ITINERARY_URL` 상수 교체로 대부분 일괄 반영
- Day 섹션 가드에 "챕터에 일정 뿌리가 되살아나면 실패" 조건 추가

### `tracker/itinerary.html` — 부록 강등

- 트래커 탭 스트립(6칸)에서 제거, `tracker/index.html` 하단에
  "시트 원본 (부록)" 링크로 이동
- 20열 표는 **그대로 둔다** — 부록의 존재 이유가 시트 원형 열람이다.
  리플로 예산의 명시적 예외(현행 1쪽)도 그대로, 주석만 "부록이라 예외"로 갱신
- 탭이 6→5칸이 되어 390px 3줄 문제(진단 5)도 완화

## 2. 대시보드 재구성 (진단 2-3, 🔴)

### 실측 — 지금 무엇이 나가고 있나

시트는 좌우 두 구역(왼쪽: 프로젝트 기준 + 단계·완성도 / 오른쪽: 예약 KPI +
P0 다음 행동)인데 변환기가 **4열 한 표**로 붙인다. 거기에 두 가지가 더 있다:

1. **예약 KPI 수량 열은 전부 빈칸으로 렌더되고 있다.** 셀이 수식인데
   `data_only=True` 로 읽으면 캐시가 없어 None — 즉 지금 화면의 KPI 표는
   제목만 있고 값이 없다.
2. **"실제 예약 잠금률 0" 은 죽은 스냅샷이다.** 현실은 예약완료 7건.
   시트에 박힌 날(8/4) 이후 갱신되지 않았다.

### 재구성안 (시안: `docs/previews/dashboard-mockup-v1.0.html`)

수치의 원칙 하나로 요약된다 — **집계는 시트에서 읽지 않고 Reservations 에서
직접 센다.** 홈·예약현황과 같은 함수(`res_headline`), 같은 분모. 화면은 세
구역으로 나뉜다:

| 구역 | 대체하는 것 | 형태 |
|---|---|---|
| **① 예약 KPI 타일** | 빈칸 KPI 표 + 죽은 잠금률 행 | 수치 타일 4장: 유효 27 · 미확정 20 · 예약완료 7 · P0 7/15 (+숙소 3/8). 각 타일 → 예약현황 해당 필터 딥링크 |
| **② P0 다음 행동** | 오른쪽 둘째 표 | 검증된 `rz-card` 재사용 — 완료/재확인/**차단(빨강)** 배지. 순서는 시트 그대로(사람이 고른 순서) |
| **③ 완성도 막대** | 왼쪽 완성도 표 | 라벨 + 막대 + % (0.93 같은 맨숫자 제거). 이 값들은 사람이 판정하므로 시트 유지 |

- '프로젝트 기준'(여행기간·지역 8)은 사이트 전역에 이미 있는 정보 — 메타
  줄로 강등
- 새 컴포넌트는 KPI 타일·막대 둘뿐, 나머지는 기존 `.rz-*` 재사용
- Phase 8 가드의 대시보드 동기 검사는 실집계로 바뀌면 조건 자체가 사라짐 —
  가드를 "타일 수치 = res_headline 결과" 대조로 교체

**시트 KPI 표는 이후 갱신 불필요** — 트래커 xlsx 의 KPI 열이 비어 있어도
화면은 항상 실집계를 낸다. 이 파일이 이 진단의 세 항목 중 유일하게
**결정 없이도 지금 구현 가능**한 것이다 (구조 변경이 아니라 렌더 교체).

## 3. 축 이름 통일 (진단 4-6)

### 실측 — 같은 축의 이름 일곱 가지

| 화면 | 표기 | 목적지 |
|---|---|---|
| 하단탭 | **일정** | chapters/itinerary.html |
| 좌표 바 축 라벨 | **일자** (값 "43일") | daily/index.html |
| daily/index h1 | **43일 실행 일정** | — |
| chapters/itinerary h1 | **전체 일정** | — |
| daily 크럼 | **데일리** | — |
| 홈 액션 | **43일 일정** / **데일리 카드 전체** | 각각 다른 페이지 |
| regions 관련 링크 | **43일 전체 일정표** / **데일리 카드 43일** | 각각 다른 페이지 |
| 트래커 카드 | **43일 전체 일정표** | tracker/itinerary.html (시트) |

"43일 전체 일정표"가 **두 개의 다른 페이지**를 가리키는 것이 최악이다
(regions → chapters/itinerary, tracker → 시트).

### 개선안 — 이름 규칙 세 줄

1. **축 이름은 "일정" 하나다.** 하단탭이 이미 그 이름이고, 사용자가 고르는
   행동("일정을 본다")과 일치한다. 좌표 바 축 라벨 '일자' → **'일정'** 으로
   (일정 · 지역 · 주제).
2. **뿌리 페이지의 이름은 "43일 일정".** h1 · 크럼 · 홈 액션 · regions 링크
   전부 이것 하나. "데일리 (카드)"는 사용자 노출 문구에서 제거 — 컴포넌트/
   코드 이름으로만 남는다. 개별 날은 지금처럼 "Day N".
3. **시트 원본은 "일정 시트 원본 (부록)".** "43일 전체 일정표"라는 이름을
   두 페이지가 나눠 갖는 일이 사라진다.

1번(축 단일화)을 B 안으로 가면 이 규칙의 적용 지점이 하나로 줄어 통일이
쉬워진다 — 두 결정은 한 PR 로 함께 가는 것이 맞다.

### 이 진단이 확인하지 않은 것

그대로다.
