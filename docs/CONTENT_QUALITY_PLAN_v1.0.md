## 0. 이 문서의 전제

**"Lonely Planet 수준"을 그대로 베끼지 않는다.** LP 는 처음 가는 불특정 독자를 위한
범용 안내서고, 이 가이드북은 **두 사람의 확정된 43일을 현장에서 굴리는 도구**다.
따라서 LP 에서 가져올 것과 버릴 것을 먼저 나눈다.

| LP 에서 **가져올 것** | 이 프로젝트에 적용한 형태 |
|---|---|
| 왜 가는가를 먼저 말하는 서술 (why-go) | 장소마다 **정체성 → 우리에게 의미 → 볼 것** 순서 |
| 역사·사회·경제 맥락을 관광정보와 분리해 싣는 것 | 이미 있는 `지역을 이해하는 다섯 개의 층` 구조 강화 |
| 운영정보의 출처·최종확인일 표기 | **모든 운영정보에 출처 + 확인일 또는 pending 배지** |
| 실용 카드(요금대·예약난이도·휴무·소요) | 표준 89 의 **식당·장소 카드 필드 전면 적용** |
| 편집자 판단을 감추지 않는 톤 | 이미 있는 `Editor's Verdict`·등급 체계 유지 |
| 장소당 사진 1장 이상 | 라이선스 검증된 로컬 사진만 (기존 원칙 유지) |

| LP 에서 **버릴 것** | 이유 |
|---|---|
| 망라형 목록(호텔 20곳·식당 30곳) | 숙소·일정이 이미 확정됐다. 선택지 나열은 현장에서 방해다 |
| 광범위한 예산·교통 개론 | 43일 실제 예약·경로가 정본이다 |
| "3일 코스 / 1주 코스" 추천 | 우리 일정이 이미 있다 |
| 별점·순위 | 표준 89 가 **편집 추천도**로 정의한 등급을 쓴다 |

**즉 목표는 "정보량 증가"가 아니라 — 확정된 43일 안에서 만나는 모든 장소가
상용 가이드북 한 항목만큼의 밀도·근거·읽는 맛을 갖는 것**이다.

## 3. 개선 라운드

각 라운드는 **독립 PR 1개 + 게이트 통과**로 끝난다. 라운드 사이에 사용자 확인을 받는다.

### R0 — 측정 도구 ✅ 완료 (2026-08-14)

`build/content_quality.py` 를 만들었다. 위 C1–C6 을 계산해 스코어카드를 출력하고
`docs/CONTENT_SCORECARD.md` 를 갱신한다. **먼저 만드는 이유: 이후 모든 라운드의 성과를
같은 자로 재기 위해서다.** 초기값은 §1 의 실측치를 baseline 으로 고정한다.

- 산출: `build/content_quality.py` · `docs/CONTENT_SCORECARD.md` (baseline 고정)
- 게이트: 스크립트가 §1 수치를 재현한다 → **재현됨.** 정의가 더 정확한 3건은 위에 반영.
- `GATES` 는 비워 뒀다 — R0 은 측정만 한다. 라운드가 끝날 때마다 그 라운드 지표를 여기서 잠근다.

### R1 — 근거 표기 (C3) ✅ 완료 (2026-08-14)

**가장 위험한 결함부터 없앤다.** 무근거 운영정보 188줄을 셋 중 하나로 처리한다.

1. 공식 출처로 확인 → 숫자 유지 + `출처 · 확인일` 병기
2. 확인 실패 → 숫자를 지우고 `{{badge:pending|공식 확인}}`
3. 우리 일정 시각(계획값) → 운영정보가 아니므로 **표기 대상에서 분리**

- 우선순위: 필수 등급 장소 → 예약·요금이 걸린 항목 → 나머지
- 게이트: **무근거 0 달성.** `content_quality.py` 의 `GATES` 에 잠갔다 — 앞으로 출처·확인일·
  pending 없이 개관시간이나 요금을 새로 쓰면 빌드가 멈춘다.
- **검출기를 먼저 정교화했다.** ① 근거를 블록에서 상속하게 했다(표 머리글·앞 문단·상위 헤딩) —
  요금 셀마다 URL 을 반복하면 표가 읽히지 않는다. ② 대신 **근거로 인정하는 표기를 좁혔다** —
  맨 '확인' 두 글자는 통과하지 않고 `계획가`·`확정` 은 날짜를 요구한다.
  조인 검출기로 다시 재니 무근거는 188 이 아니라 **237** 이었다.
- **표준 90 의 '계획가격 vs 확정가격' 을 구현했다.** 식당 메뉴·예산·주차 요금은 지우지 않고
  `계획가(2026-08 조사)` 로 표시했다 — 값을 버리면 예산 설계가 불가능해지고, 확정처럼 두면
  규칙 4 위반이다.
- **공식 확인 13건을 Phase 10 레지스터에 등재했다** (F024–F036). 23 → **36건.**
  목표 60건에는 못 미친다 — 나머지는 R2·R4 에서 새로 쓰는 장소·식당과 함께 채운다.

### R2 — 커버리지 (C1) ✅ 완료 (2026-08-14)

본문 없는 spot 13개를 채운다. **Cannes·Monaco 가 최우선** — 각각 하루를 쓰는 목적지다.

  레지스트리에 별칭 열을 두어, 이미 쓴 글이 그 장소 페이지에 나타나게 한다.
  **없는 글을 쓰기 전에 있는 글을 연결하는 것이 순서다.**
- 연결 후에도 비는 장소만 신규 집필한다. 각 장소를 등급 기준 분량으로 작성(§2 표), 사진 후보 조사 병행
- 레지스트리 `본문`·`위키` 열을 함께 채운다
- 게이트: 레지스트리 `—` 0 · 신규 서술 전부 C3·C4 충족

**실행 결과:**

- **신규·승격 본문 13곳** — Cannes·Monaco 는 why-go·역사 맥락·관람 순서·실용표를 갖춘 본문으로
  새로 썼고, Girona 권 7곳(대성당·Onyar·Collioure·Pals·Peratallada·Peralada·Calella)과
  Sitges·Rotonde·L'Isle-sur-la-Sorgue·Bellecour 는 흩어져 있던 서술을 등급 헤딩으로 승격·보강했다.
- 신규 운영정보는 전부 출처·확인일 또는 pending 배지를 갖는다 (C3 무근거 0 유지).
- 등급 미정 2 (Rotonde·Bellecour) → **0** — 선택 등급으로 확정.
- 게이트 잠금: `본문 없는 spot 0` · `dossier 이름 불일치 0`.
- **위키 없음 10 은 남겨 뒀다** — '확인한 것만 채운다' 원칙. 제목을 검증하지 않고 채우면
  남의 문서가 이 장소처럼 연결된다.

### R3 — 서술 밀도 (C2·C4) ✅ 완료 (2026-08-14)

dossier 51개를 스텁에서 상용 항목으로 올린다. 순수 서술 중앙값 **41자 → 400자 이상**
(표 포함 전체 242자 → 700자 이상).

- 각 항목에 **why-go 문단**(왜 이곳이 이 여행에서 의미가 있는가)을 추가한다
- 역사·문화 맥락과 운영정보를 분리한다 (표준 90 의 `변동정보 원칙`)

- 게이트: C2 등급별 하한 100% · C4 7요소 100%

**실행 결과 — 측정 대상을 먼저 교정했다.**
- **dossier(90)는 사이트에 렌더되지 않는 빌드 보조 문서다** (공식 URL 의 소스). 안 보이는 문서를
  살찌우는 것은 품질이 아니므로, C2·C4 의 측정 대상을 **독자가 읽는 챕터 등급 절**(places.html
  원고)로 바꿨다. 측정기 결함 두 건도 함께 수정 — `**볼드` 문단을 목록으로 오인, 사진 헤딩이
  절을 조기 종결.
- 교정된 자로 잰 baseline: 등급 절 96 · 서술 중앙값 187자 · **하한 미달 81**.
- 8개 챕터 65개 절(재측정 후)을 전부 하한 위로 보강했다 — why-go·역사 맥락·관람 동선·현장
  운영 팁. 새 운영 수치는 넣지 않았고(기확인 값 재사용 또는 pending), 역사 서술은 널리 확립된
  사실로 제한했다.

### 회귀 방지 — 게이트화

R0 의 스크립트를 **빌드 가드로 승격**한다. 라운드가 끝날 때마다 그 라운드의 지표를
`content_quality.py` 의 하한으로 잠근다. 이후 원고를 늘릴 때 기준 미달 서술이 들어오면
**빌드가 멈춘다.** (기존 17종 상위 게이트와 같은 방식)

### 품질을 자동으로 잴 수 없는 것

문장의 읽는 맛, 편집자 판단의 설득력, 사진의 적절성은 스크립트가 판정하지 못한다.
이 셋은 **라운드마다 표본 검토**로 확인한다 — 지역당 필수 등급 2개를 뽑아
"처음 가는 사람이 이 글만 읽고 그 장소를 이해하고 찾아갈 수 있는가"를 기준으로 읽는다.
**검사 통과를 품질 달성이라고 보고하지 않는다.**
