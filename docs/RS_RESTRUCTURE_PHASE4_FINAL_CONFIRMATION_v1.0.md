## 0. 사용자 결정 사항 (선반영)

### 결정 1 — 감량률 기준 개정 (승인됨)

7개 지역 전부가 통일 측정법에서 54~73% 대역으로 측정되었다. 이는 특정 지역의 실패가 아니라 Place Dossier 분리 아키텍처의 구조적 결과다. 따라서 **감량률 기준을 다음과 같이 개정한다.**

| 구분 | 기존 | **개정** |
|---|---|---|
| 감량률 | 30–45% (상한 있음) | **30% 이상, 상한 없음** |
| 추가 필수 조건 | — | **핵심 사실·편집 판단·실무정보 유실 0건** |
| 추가 필수 조건 | — | **감량분의 이관처가 Place Dossier 등으로 명시됨** |
| 30% 미만 | 재작업 | 재작업 (유지) |

* 이 기준은 **Phase 2~5 전체에 소급 적용**한다.
* 감량률은 이제 단독 합격 기준이 아니라 **유실 0건 증빙과 함께 판정하는 참고 지표**다.
* 따라서 Barcelona 66.9% / Girona 62.6%는 **§2의 유실 0건 증빙이 성립하면 합격**이다.

## 1. Day 번호 — 자기모순 해소 (BLOCKING)

보완 보고의 두 문장이 서로를 부정한다.

> (a) "Day 1**~**4가 Day 14로, Day 4**~**7이 Day 47로 기재된 건입니다"
> (b) "실제 일정 데이터는 **글로벌 일차(Day 14 / Day 47)**와 한 치의 오차 없이 정합"

(a)는 진짜 범위가 **Day 1–4 / Day 4–7**이라는 뜻이고, (b)는 파일에 **Day 14 / Day 47이 실재**한다는 뜻이다. 둘 다 참일 수 없다. 43일 일정에서 Day 47은 존재할 수 없다.

### 회신 방식

추론하거나 재설명하지 마라. **파일에서 읽은 원문을 그대로 인용하라.**

1. `04_Barcelona_Sitges_v2.0.md`에서 Day 헤딩이 나타나는 줄을 **전부 원문 그대로** 붙여넣어라.
2. `05_Girona_Collioure_Emporda_v2.1.md`에 대해 같은 작업을 하라.
3. 위 인용을 근거로 두 지역의 글로벌 Day 범위를 한 줄로 확정하라.
4. 인용된 값 중 43을 초과하는 Day 번호가 하나라도 있으면 **즉시 중단하고 보고하라.**

> (b)와 같은 확인 문장은 파일을 실제로 읽지 않고 요약문을 되풀이했을 때 나온다. 이번 회신에서는 인용 없이 "정합함"이라고만 쓰지 마라.

## 2. 유실 0% 증빙 (감량률 합격의 전제)

"원문 내용의 실제 유실량 0%"를 주장했다. 개정된 기준에서 이 증빙이 **감량률 합격의 유일한 조건**이 되었으므로 근거를 제출하라.

1. **이관 매트릭스** — Barcelona·Girona 챕터에서 제거된 서술 블록이 각각 어느 Place Dossier / Walk / Daily의 어느 항목으로 갔는지 대응표.
2. 이관되지 않고 **삭제된 블록**이 있다면 전부 목록화하고, 각각이 다음 중 무엇인지 분류하라.
   * 내부 제작표현·자리표시자·폐기안 (삭제 정당)
   * 다른 위치에 이미 존재하는 중복 (삭제 정당)
   * 그 외 (**유실. 즉시 보고**)
3. 유실 0%를 어떤 방법으로 판정했는지 명시하라. 자동 비교라면 스크립트를, 표본 대조라면 대조한 블록 수를 밝혀라.

## 3. 누락된 실측값 6종

QA 문서에 기록했다면 **그 수치를 그대로 회신에 옮겨 적어라.** "문서에 있음"은 회신이 아니다.

| # | 항목 | 요구 형식 |
|---|---|---|
| 1 | Place 11개 필드 충족률 | `%` 및 미충족 장소·필드 목록 |
| 2 | Registry–Dossier | missing `n` / orphan `n` / duplicate `n` |
| 3 | 일정·사실 보존 diff | 비의도 변경 `n`건 |
| 4 | 수동 표본검수 | 읽은 파일 수 및 발견 결함 `n`건 |
| 5 | Daily 삭제 순서 | 대상 Daily 중 존재 `n` / 결측 `n` |
| 6 | `05_..._v2.1.md` 버전 | 의도된 버전인지 / 파일명 규칙 위반인지 |

4번은 결함 0건보다 **정직한 결함 목록**이 낫다. 자동 이관된 Place를 읽었다면 어떤 것을 읽었는지 파일명을 밝혀라.

## 4. 추가한 검증 코드의 실효성

`build/build.py`에 피로도 누락 검증(`if fat_missing:`)을 추가했다. 방향은 옳으나 보완 지시문 §0의 "검사 코드를 수정하지 마라" 범위를 벗어났으므로 다음을 확인하라.

1. 해당 변경의 **diff 전문**을 제시하라.
2. **네거티브 fixture로 실효성을 증명하라.** 임의의 Daily에서 피로도 줄을 제거했을 때 빌드가 실제로 FAIL하는지 재현하고 결과를 붙여라. 가드가 추가되었으나 작동하지 않는 경우가 가장 위험하다.
3. 이 가드가 **Nice·Aix·Luberon·Avignon·Lyon의 Daily에도 적용**되며 전부 통과하는지 확인하라. 통과한다면 지역 비의존성이 실증된 것이다.
4. Phase 3A의 네거티브 fixture 목록에 이 케이스를 **10번째 항목으로 추가**하라.
